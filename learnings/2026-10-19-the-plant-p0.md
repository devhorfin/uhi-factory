# Learnings — THE PLANT P0 (2026-10-19)

**Problem:** an isometric live simulation of the agent workforce, driven by the real event stream, with generated art, in one session.

## What worked
1. **gpt-image-1 with `background: "transparent"` returns real alpha PNGs** (alpha min 0, corner pixels transparent). The image viewer shows transparent as grey, which looks like a failure; check the alpha channel before adding a chroma-key step. No rembg needed. 25 sprites at medium quality cost about $1 (≈1,056 output tokens each).
2. **One material line appended to every prompt** ("brushed chrome and dark bevelled steel, black studio backdrop, cool white highlights, a hint of cyan, photographic product render, isometric") keeps 25 separate generations looking like one kit.
3. **Static layer once, dynamic layer per frame.** Floor, walls, stations and belt are drawn to an offscreen canvas on resize; per frame only robots, crates, lamps and text. 61 fps at both viewports with 25 bots.
4. **Per-robot event queues** (walk / work / pickup / shrug) keep bursts of events from skipping the output or the grade; crates on the belt wait at the gate until the grade arrives.
5. **A `?view=` URL parameter** makes a toggled view capturable by the headless tool, which has no localStorage.

## Dead ends
- Wall "segments" drawn every two tiles by height produced gaps; size wall sprites by **width** (one per tile, 1.06 tiles wide) so they join.
- `browse screenshot` came back at 95–513 px wide after server restarts (the known capture glitch); `studies/tools/capture.cjs` with the `?view=plant` URL gave proper 1280 and 860 px shots.
- The generated floor tile is a square slab at the isometric angle, not a 2:1 diamond; squashing it to 2:1 reads fine, but next time prompt for "a flat rhombus exactly twice as wide as tall".

## Reusable rule
Generated sprites with transparent background + a shared material line + a static/dynamic split renderer + event queues per actor = a live isometric scene in a day. Check alpha before cutting out; capture toggled views through a URL parameter.

- **Tap on a hall did nothing (v0.5.0):** the overview card object was `{ h, x, y, w, h: ch }`: the height key overwrote the hall key, so the hit test passed but `enter(c.h.id)` got a number. Renamed to `hall` / `hh`. Lesson: never reuse a shorthand property name as a key in the same literal; test taps with a dispatched PointerEvent pair, which reproduces it headlessly.
